# Phase 1 — `phase1-baseline-v2`

End-to-end Phase 1 run. Trained `MaskablePPO` with a custom `BoardCNN` extractor
against `WeightedRandomPlayer` in 1v1, using Charlesworth-style reward shaping,
on a M3 Pro (MPS).

**W&B:** https://wandb.ai/nauqs/catan-rl/runs/uxqv42h2
**Steps trained:** 38,010,880 of a planned 50M (manually stopped at the
plateau — see "Why we stopped early" below)
**Checkpoint used for analysis:** `model.zip` (final), with `best.zip`
preserved separately.

---

## Setup

| | |
|---|---|
| Algorithm | `MaskablePPO` (sb3-contrib 2.8) |
| Observation | Catanatron `representation="mixed"`: `{board: (16, 21, 11) tensor, numeric: (48,) vector}` |
| Architecture | `BoardCNN`: 3 conv layers (16→32→64→128, 3×3 pad=1, ReLU) → GAP → linear(256); numeric MLP `48→256→256`; concat → 512-dim features → SB3 default `[256, 256]` actor & critic heads (~700k params total) |
| Action space | Flat `Discrete(332)`; `NoTradeWrapper` masks off the 60 `MARITIME_TRADE` indices |
| Training opponent | `WeightedRandomPlayer` (single, fixed) |
| Reward shaping | Charlesworth-style (his exact values, see below) |
| PPO HPs | γ=0.999, λ=0.95, n_steps=2048, batch=512, ent_coef=0.01, lr=3e-4 |
| Parallelism | `SubprocVecEnv` × 8 envs |
| Device | MPS (3.2× faster than CPU at this network size) |
| Wall-clock | ~17 h for 38M steps (~610 sps actual, vs 406 sps in the 20k profile) |

### Reward function (Charlesworth's exact values, from his `env/wrapper.py`)

Applies only to the trainable agent (BLUE), not to opponents.

| Event | Reward | Catanatron mapping |
|---|---|---|
| Terminal: agent wins | **+500** | overrides Catanatron's +1 |
| Terminal: agent loses | **0** | overrides Catanatron's −1 (positive-only terminal) |
| VP gained (delta from prev step) | **+5 per VP** | computed from state |
| Play any development card | **+5** | `PLAY_KNIGHT_CARD`, `PLAY_YEAR_OF_PLENTY`, `PLAY_ROAD_BUILDING`, `PLAY_MONOPOLY` |
| Move robber | **+1** | `MOVE_ROBBER` |
| Forced discard | **−0.3** | `DISCARD_RESOURCE` |
| Upgrade to city | **+2.5** (bonus, additional to +5 from the VP delta) | `BUILD_CITY` |

Dense-reward annealing was wired in but defaulted to off (matching Charlesworth's defaults).

## Final results (500 games × 5 opponents × 1v1)

`model.zip` evaluated with `deterministic=True` via `RLPlayer`. Full JSON at `final_ladder.json`.

| Opponent | Winrate | 95% CI | Mean VP | Mean turns | Eval time |
|---|---|---|---|---|---|
| RandomPlayer | **80.0%** | [76.3%, 83.3%] | 9.18 | 280 | 118s |
| WeightedRandomPlayer | **71.0%** | [66.9%, 74.8%] | 8.91 | 266 | 112s |
| ValueFunctionPlayer | **9.2%** | [7.0%, 12.1%] | 4.97 | 85 | 94s |
| AlphaBetaPlayer (n=1) | **12.6%** | [10.0%, 15.8%] | 5.32 | 88 | 97s |
| AlphaBetaPlayer (n=2) | **7.4%** | [5.4%, 10.0%] | 4.79 | 85 | 472s |

**Where this sits.** Comfortably beats Random and Weighted (the latter is its
training distribution). Cannot beat Value/AlphaBeta — same plateau pattern as
bcollazo's TensorForce baseline (~80% vs Random, never catches Value). Curious
wrinkle: **AlphaBeta-1 (12.6%) is the easiest of the three strong bots** — the
agent has likely learned to exploit a weakness in AB-1's exact decision style
that Value and AB-2 don't expose.

### Why we stopped early at 38M / 50M

W&B chart of in-training winrate showed a clear plateau by ~20–25M steps with
no upward movement through 38M. The plateau is structural (curriculum, not
training budget) — see "Phase 2 recommendations" below.

## Behavioral analysis (200 games each, final checkpoint)

JSON at `analysis_vs_{random,weighted,value}.json`. Generated by
`scripts/analyze.py`.

### Overview

| | vs Random | vs Weighted | vs Value |
|---|---|---|---|
| Winrate | 86.5% | 79.5% | 9.0% |
| Mean VP | 9.63 | 9.28 | 4.82 |
| Mean turns | 252 | 250 | **84** |
| Settlements (final) | 2.49 | 2.31 | 2.01 |
| **Cities (final)** | **1.09** | **1.15** | **0.50** |
| Roads (final) | 10.7 | 10.3 | 6.8 |
| Roads / building | 2.99 | 2.99 | 2.73 |
| Dev cards bought | 8.55 | 8.26 | 3.06 |
| Knights played | 4.70 | 4.52 | 1.68 |
| Robber-steals on opponent | 23.2 | 22.6 | 8.65 |
| **Initial pip sum / settl.** | 9.91 | 9.83 | 9.68 |
| Initial 3+ resources | 49% | 48% | 41% |
| **Initial port** | **0%** | **0%** | **0%** |

(The 200-game winrates differ from the 500-game ladder by ~5pp; both are
within their respective CIs.)

### What the agent has clearly learned

- **Picks reasonable initial spots.** Pip sum ~9.8–9.9 per settlement
  (≈5 pips/settlement — solid on a 6/8 + a 5/9 or similar). It does prefer
  high-pip tiles.
- **Robber discipline.** Almost every `MOVE_ROBBER` targets an opponent, not
  itself (~22 of ~22 per game vs Random/Weighted).
- **Dev-card-and-knights as a primary VP route.** ~8.5 cards bought per game,
  ~4.5 knights played, contributing ~33% of total VPs (largest army +
  hidden VP cards combined).
- **Long, controlled games against weak opponents.** Mean turn count ~250
  vs Random/Weighted is well above Catan baseline — the agent isn't rushing,
  it's grinding out wins.

### What the agent has *not* learned

- **Cities are under-built.** Only ~1.1 cities/game vs Random/Weighted, **0.5
  vs Value**. Distribution is bimodal: either the agent commits to cities
  (2+ per game) or builds none.
- **Ports completely ignored.** **0% of initial settlements** are on a port;
  4–17% of final buildings touch a port (likely accidental). This is a
  structural artefact of `NoTradeWrapper` — with all `MARITIME_TRADE`
  actions masked off, ports have *no functional value*. The agent is
  technically correct to ignore them.
- **Resource variety is mediocre.** 2.4 distinct resources / initial
  settlement, 48% on 3+. Better than random placement, not Catan-optimal.
- **Cannot survive against Value.** Mean game length collapses from
  ~250 → 84 turns. Agent never reaches its dev-card-and-largest-army
  endgame because Value closes out first.

### Cities per game — bimodal

| #cities | vs Random | vs Weighted | vs Value |
|---|---|---|---|
| **0** | 35.5% | **48.5%** | **70.0%** |
| 1 | 20.0% | 17.0% | 14.0% |
| 2 | **31.5%** | 26.0% | 13.5% |
| 3 | 9.5% | 8.0% | 2.5% |
| 4 | 3.5% | 0.5% | 0% |

The agent rarely builds *exactly one* city — either all-in on cities (2+) or
none. Suggests the policy committed to a strategy at initial-placement time
(ore/wheat availability) and doesn't adapt mid-game.

### VP source decomposition

| | vs Random | vs Weighted | vs Value |
|---|---|---|---|
| Buildings (settl. + city) | 4.66 (50%) | 4.28 (48%) | 3.08 (63%) |
| Longest road (2 if held) | 1.63 (17%) | 1.50 (17%) | 0.46 (9%) |
| Largest army (2 if held) | 1.38 (15%) | 1.22 (14%) | 0.67 (14%) |
| VP dev cards (hidden) | 1.74 (18%) | 1.87 (21%) | 0.71 (14%) |
| **Total VP** | **9.40** | **8.86** | **4.86** |

Buildings carry ~50% of points; the dev-card/largest-army composite carries
~33%. Vs Value the agent is forced into buildings because Value ends the game
before the dev-card route matures.

### Win-vs-loss conditional (vs Value: 16W / 184L over 200 games)

| | Wins | Losses |
|---|---|---|
| Mean turns | 81 | 85 |
| **Mean cities** | **1.19** | **0.42** |
| Mean VP | 10.06 | 4.46 |

**Wins have 2.8× more cities than losses, in the same number of turns.** The
agent isn't winning by surviving longer vs Value — it's winning by reaching 10
VPs around the same time, *and cities are the differentiator*.

For vs Random/Weighted **losses**: mean turns are 516 and 601 respectively —
these are mostly `TURNS_LIMIT` truncations, i.e. stalemates the agent failed
to close out. ~13–25% of "losses" against weak opponents are stalls.

### Reward attribution — where the policy is being "paid"

Per-game totals; share is fraction of total reward magnitude.

| source | vs Random | vs Weighted | vs Value |
|---|---|---|---|
| terminal_win | +420 (**72%**) | +372 (71%) | +40 (42%) |
| vp_delta | +47 (8%) | +44 (9%) | +24 (26%) |
| dev_play | +33 (6%) | +32 (6%) | +14 (15%) |
| robber | +27 (5%) | +26 (5%) | +9 (9%) |
| **discard** | **−49 (8%)** | **−45 (9%)** | −6 (7%) |
| **city_bonus** | **+3 (0.5%)** | **+2 (0.5%)** | +1 (1%) |

**Two big surprises:**

1. **`city_bonus` is invisible to the policy** — 0.5% of reward magnitude. Cities are
   *empirically* the difference between winning and losing vs Value (2.8× more in
   wins), but the shaping signal that would reward city upgrades is dominated by
   everything else.
2. **`discard` penalty totals ~−47/game** — comparable to *all* the positive dense
   signals combined. This is likely driving the agent to spend resources on
   anything (especially dev cards) just to avoid hitting hand-size > 7 on a 7-roll.
   8.5 dev cards/game is suspiciously high.

## Phase 2 recommendations (data-driven)

### Reward shaping changes

| Change | Current | Proposed | Why |
|---|---|---|---|
| `CITY_BONUS` | +2.5 | **+10 to +15** | Currently 0.5% of reward signal; cities are 2.8× more frequent in vs-Value wins than losses. The strongest available data-driven recommendation. |
| `DISCARD_PENALTY` | −0.3 | **−0.05 or remove** | Totals −47/game — same magnitude as all positive dense signals combined. Probably causing dev-card-spam behavior. Discards from rolling 7 are largely outside agent control anyway. |
| `DEV_PLAY_REWARD` | +5 | **+2** | Currently overweighted vs actual win contribution. The agent is being paid to *use* dev cards, not to *win* with them. |
| Loss reward | 0 | **−500** (symmetric) OR small per-turn penalty | Currently no penalty for stalling — ~13–25% of losses vs Random are stalemates the agent never closes. |

### Curriculum (the bigger lever)

- **Mix `ValueFunctionPlayer` into training.** Currently single-opponent
  `WeightedRandomPlayer`. The 9% winrate vs Value at 38M steps shows the
  gradient *can* flow against Value (terminal +500 fires often enough). A
  70/30 weighted/value mix per env would give the agent direct exposure to
  the play style it's currently blind to.
- **Self-play stays parked for now.** Bigger engineering lift; only attempt
  once the simpler curriculum + reward fixes have been tried.

### Specific Phase 2a experiment

Smallest change with the largest expected impact:

```yaml
train:
  opponent: weighted        # could also try: mix [weighted, value]
  reward:
    enabled: true
    city_bonus: 10.0         # was 2.5
    discard_penalty: -0.05   # was -0.3
    dev_play_reward: 2.0     # was 5.0
    loss_reward: -500        # was 0 (implicit)
```

Train for 20M steps, compare cities/game vs Value (target: 0.5 → ≥1.5) and
winrate vs Value (target: 9% → ≥20%).

### What we are *not* doing in Phase 2 (yet)

- Multi-head action architecture (Charlesworth's biggest engineering lift).
  Park until reward + curriculum changes plateau.
- Tile self-attention. Same reasoning — engineering before evidence.
- Restoring trades / making ports useful. Big design change; data doesn't
  point at this as the bottleneck.
- 4-player training. Phase 1 was 1v1 only; if 1v1 plateaus past Value, then
  consider 4p as a separate axis.
